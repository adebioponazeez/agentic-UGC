# REVERSE ENGINEERING FRAMEWORK v1.0
## Non-copying structural extraction from 20M–500M subscriber channels

---

## PROTOCOL OVERVIEW

Every reverse-engineered insight must pass 7 enforcement checks before integration:

```
1. SELECTION (algorithm validates range + vertical + originality + evidence)
2. EXTRACTION (14 dimensions analyzed with timestamped evidence)
3. VALIDATION (matches against Creative Memory — validated / rejected / new experiment)
4. TRANSFORMATION (design derivative — not duplicate — with identity claim)
5. ANTI-CLONING (7 governance checks enforced by OMEGA-M4)
6. RED TEAM (10 critics review transformed proposal — not original competitor)
7. MEMORY INTEGRATION (writes to Creative + Strategic + Failure with explicit references)
```

---

## EXECUTION SEQUENCE (AGENT: OMEGA-Y1 + E1 + M4)

```
STEP 1: COMPETITOR SELECTION
Agent: OMEGA-Y1
Input: Strategic thesis (channel vertical, format approach, audience segment, monetization model)
Algorithm: Filter channels by subscriber range (20M–500M) + vertical alignment (≥2 of 4 dimensions) + performance validity + originality + evidence integrity
Output: competitor_selection.json (structured selection with evidence URLs, selection reasoning, exclusion reasons for rejected candidates)
Memory: Write to OPERATIONAL (selection log) + WORLD (competitive landscape entities)

STEP 2: STRUCTURAL EXTRACTION
Agent: OMEGA-Y1 (with F1–F5 contracts for dimension analysis)
Dimensions: 14 (see SOP Section 3.2)
Evidence: Every observation requires video URL + timestamp reference + direct quote / visual description + source verification
Output: competitor_[id].json (structured 14-dimension analysis)
Memory: Write observations to CREATIVE (pattern observations — labeled as unvalidated until transformed)

STEP 3: MEMORY VALIDATION
Agent: OMEGA-M4 (Governance Guardian) + automated comparison
Compare competitor patterns against Creative Memory entries:
- If exact match exists and validated: reference existing pattern
- If similar but different: treat as new experiment proposal
- If no match: new pattern — requires red team + quality engine verification before validation
- If rejected pattern exists: automatic rejection reason documented
Output: validation_report.json
Memory: Update CREATIVE with observation tags (validated/rejected/new_experiment/rejected_duplicate)

STEP 4: TRANSFORMATION DESIGN
Agent: OMEGA-C1 (Content Strategist) + OMEGA-F1 (Story Development)
Requirements: Every transformed proposal must include explicit identity claim, format difference description, depth difference evidence, emotional difference target, evidence framework difference, and strategic alignment confirmation.
Output: transformation_plan.json (links competitor insight to new series architecture)
Memory: Write transformation plan to STRATEGIC (competitive strategy update) + OPERATIONAL (design document)

STEP 5: ANTI-CLONING GUARDIAN CHECK
Agent: OMEGA-M4
Checks (all 7 must pass):
1. Identity claim verified (not generic narration, not cloned voice)
2. Format difference documented (different structure, duration, visual approach)
3. Depth difference verified (new evidence, new analysis, new perspective)
4. Emotional difference confirmed (serves different audience need)
5. Evidence difference verified (different sources or verification methods)
6. Memory integration plan includes new pattern contribution (not replication)
7. Strategic alignment confirmed (serves our thesis — not competitor's)
Output: anti_cloning_report.json (PASS / FAIL per check + aggregate)
Memory: Write to OPERATIONAL (governance log) + FAILURE (if any check fails)

STEP 6: RED TEAM REVIEW
Agent: OMEGA-M2 (Council Leader) + 10 critics
Target: The TRANSFORMED proposal — not the original competitor
Criteria: Same 5-score framework (C, T, P, B, R) applied to new output design
Output: red_team_review_transformed.json
Memory: Write review to OPERATIONAL + CREATIVE (if validated) + FAILURE (if rejected/rework)

STEP 7: MEMORY INTEGRATION + EVOLUTION PROPOSAL
Agent: OMEGA-M1 (Self-Evolution) + OMEGA-0 (Orchestrator)
Actions:
- Integrate validated competitor patterns into Creative Memory (with source reference and transformation note)
- Update Strategic Memory (competitive landscape, strategic thesis adjustments)
- Write any failure/rework/abandon reasons to Failure Memory
- Propose evolution (if validated patterns suggest new format, new series, new product opportunity)
Output: evolution_proposal.json (if applicable) + final_memory_sync_log.json
```
